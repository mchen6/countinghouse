# RC1-min Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A module declares one remote MCP server. The main thread
connects to it with the operator-allowed credential, and
`ctx.call('remote:<name>/<tool>', args)` returns the server's raw
`CallToolResult`, metered and counted.

**Architecture:** New `lib/remote/`:
- a declaration parser;
- the operator's allowance;
- a fetch adapter over `node:http`/`node:https` (lookup hook, no
  redirects, a byte cap, a timeout) that the SDK's
  `StreamableHTTPClientTransport` uses;
- a client per module;
- a registry keyed by the module's load name.

`handler-ctx.js` routes `remote:` addresses. In worker mode they cross to
the parent as one new worker message, and the parent resolves the remote
by the worker's own module. In single-thread mode they call the registry
directly.

**Tech Stack:** Node ≥ 24.15. `@modelcontextprotocol/sdk` 1.32.2, already
pinned: `Client`, `StreamableHTTPClientTransport`, and `McpServer` with
`StreamableHTTPServerTransport` for the test server. mocha. No new
dependency.

**Spec:** `docs/superpowers/specs/2026-11-11-rc1-min-remote-mcp-design.md`
(PR #47: 614376d, plus the round 2 edit cfb8605).

## Global Constraints

- One remote per module. `transport` is only `"streamable-http"`.
- A credential is read only when `--remoteCredentials` allows that
  variable for the declared URL's exact origin. A module cannot choose
  where a credential goes.
- The token never appears in a worker message, the worker's environment,
  a log line, an error message, a usage record or a result.
- Test tokens are synthetic and low-entropy:
  `'ghp_' + 'A'.repeat(36)`, built in code, never written as a literal in
  a test or a fixture (GitGuardian scans every PR).
- The result is returned exactly as the server sent it; `isError` is a
  result.
- New error codes go in `lib/error-catalogue.js`, each with its kind and
  retryable flag as the spec lists them.
- Options:
  - `--remoteCredentials <file>`;
  - `--remoteTimeout <seconds>` (default 60);
  - `--remoteMaxBytes <n>` (default 16777216).
- Process:
  - locally, run only the task's own new test file for RED and GREEN,
    plus `npx eslint .`;
  - take the suite lock around each `git commit`, for the pre-commit
    hook's fixed mcp-contract ports, and release it right after;
  - each task is its own branch and PR, based on the previous task's
    branch until that one merges; CI is the gate;
  - commit trailer `Co-Authored-By: Claude Opus 5.5
    <noreply@anthropic.com>` only.
- Files A owns: `lib/remote/`, `lib/handler-ctx.js`. Shared, touched
  minimally (C informed):
  - `lib/worker-message.js`: one message pair;
  - `lib/module-manager.js`: registration in `spawnModuleWorker`, and one
    listener;
  - `lib/cli-options.js`, `framework.js`, `lib/module-validator.js`,
    `lib/error-catalogue.js`.
- Test ports: 9686–9689 for test/remote 01–05's remote and listener
  ports, and the block 9720–9729 the reviewer assigned for step 3 onward
  (step 3's two servers: 9720–9721). `test/ports.md` lists the blocks and
  every test file's ports; a new port adds its row in the same PR. New tests live in `test/remote/`,
  and Task 1 adds `mocha --exit ./test/remote/*.js` to `npm test`, after
  the sandbox folder.

## Review Focus

1. A module reload or removal: the old client is closed and replaced. A
   call in flight on it rejects with `REMOTE_UNREACHABLE` rather than
   hanging, and no socket is left open (Task 3,
   `05-route.js: a reload closes the old client`).
2. A server that answers `tools/call` as `text/event-stream` rather than
   JSON: it streams through the adapter, and the byte cap counts the
   stream (Task 2, `03-client.js: an SSE answer arrives whole, and an
   oversized SSE answer is cut off`).
3. Header names that differ only in case, inside `headers`, or between
   `headers` and the credential header: refused as duplicates, so the sent
   set is never ambiguous (Task 1,
   `01-declaration.js: header names are compared case-insensitively`).
4. The credential variable is set after the server started: it is read at
   load, so a later change needs a reload. Ruling while building step 3:
   a running process's environment cannot change from outside it, so the
   test is "unset at load gives REMOTE_CREDENTIAL_MISSING". Under that rule a call made
   before any reload still rejects `REMOTE_CREDENTIAL_MISSING` (Task 3,
   `05-route.js: a variable set after load is not read until reload`).
5. Non-text content (an image or a resource item) in a result: passed
   through untouched and counted as 0 bytes, so the counter never throws
   on it (Task 5,
   `07-counting.js: non-text content is passed and not counted`).
